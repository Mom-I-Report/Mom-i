# 프롬프트 설계 문서

> 작성일: 2026-05-28  
> 대상 파일: `backend/app/infrastructure/llm/prompts/`

---

## 프롬프트 파일 구조

```
prompts/
├── system.md          # AI 역할 정의, Hard Rules, 스타일
├── knowledge.md       # 수면 도메인 지식 (판단 기준 전체)
├── reasoning.md       # 데이터 분석 순서 및 해석 원칙
├── output_format.md   # JSON 출력 구조 및 작성 규칙
├── input_template.md  # 사용자 입력 템플릿 (변수 치환)
└── age_policy.md      # 월령별 허용 수면법 목록
```

Gemini 호출 시 조합 순서: `system.md` + `knowledge.md` + `reasoning.md` + `output_format.md` → system_instruction  
`input_template.md` → user prompt (변수 치환 후)

---

## 각 파일 역할

### system.md — AI의 정체성과 원칙
**역할**: AI가 어떤 존재인지, 어떤 방식으로 답해야 하는지 정의.

핵심 3가지 역할 (2026-05-28 개선):
1. **공감**: 한국 부모의 분리수면 불안 인정 → 과학적 근거로 방향 제시
2. **분석**: 일별 데이터의 패턴·상관관계를 수치로 제시
3. **실행**: "오늘 밤 [시간]에 [구체적 행동]" 수준으로 구체화

Hard Rules (변경 금지):
- 의료 진단 표현 절대 금지
- 효과 단정 금지 ("개선됩니다" → "도움이 될 수 있어요")
- 부모 비난·불안 유발 금지
- 발열 의심·호흡 이상 시 소아과 상담 필수

---

### knowledge.md — 판단 기준 백과사전
**역할**: AI가 데이터를 해석할 때 참조하는 도메인 지식 전체.  
**이 파일이 좋을수록 출력 품질이 올라간다.**

2026-05-28 추가된 개념:

| 개념 | 설명 | 중요도 |
|------|------|--------|
| 각성 창 (Wake Window) | 월령별 깨어 있을 수 있는 최대 시간. 초과 = Overtired | ★★★ |
| Drowsy But Awake | 졸리지만 눈 뜬 상태로 눕히기. 수면 독립의 핵심 | ★★★ |
| Sleep Prop | 잠들기 위해 필요한 외부 조건. 야간 각성 반복의 주원인 | ★★★ |
| 분리수면 시작 기준 | 월령별 준비도 + 한국 문화 맥락 | ★★★ |
| 수면 퇴행 상세 | 4개월/8개월/12개월/18개월/24개월 각 원인·대처·지속기간 | ★★ |
| 분리불안 대처 루틴 | 4단계 루틴 (굿나잇→예고→피크어부→낮접촉) | ★★ |
| 취침 루틴 구성 | 권장 순서 및 수유 타이밍 | ★★ |
| 환경-수면 상관관계 | 일별 환경 ⚠ 표기된 날 수면 지표 교차 분석 기준 | ★★★ |
| 수면 교육법 상세 | 권장 월령 + sleep_guide 선택 기준 포함 | ★★ |

### reasoning.md — 분석 우선순위
**역할**: 데이터가 주어졌을 때 어떤 순서로 무엇을 봐야 하는지 지시.

분석 우선순위 (2026-05-28 정의):
1. 안전 이슈 (호흡+체온 이상 → 소아과)
2. 환경-수면 상관관계 (일별 데이터 교차 분석)
3. 수면 퇴행·발달 이슈
4. Sleep Prop 여부
5. 루틴·취침 시간
6. 긍정 패턴 (반드시 포함)

---

### output_format.md — JSON 출력 구조
**역할**: Gemini가 출력해야 하는 JSON의 정확한 스펙.

```json
{
  "ai_comment": [...],       // 2~4개, type: caution/good/tip/developmental
  "sleep_guide": {...},      // 수면 교육법 가이드 (4개월 미만 = null)
  "age_kick": {...},         // 이번 월령 발달 이슈
  "parent_message": "..."    // 부모 응원 메시지
}
```

2026-05-28 변경:
- `ai_comment` type: caution/good → caution/good/**tip/developmental** 추가
- `sleep_guide.steps`: 3단계 나열 → **Day 1 / 3일째 / 1주일째** 시간축
- `kick_action`: 구체적 시간 포함 강제 ("오늘 밤 [시간]에 ~")

---

### input_template.md — 사용자 입력 포맷
**역할**: 리포트 생성 시 Gemini에 전달되는 데이터의 템플릿.

주요 변수: `{{age_month}}`, `{{avg_sleep}}`, `{{wake_count}}`, `{{temperature}}`, `{{pattern_summary}}`

실제 상세 데이터는 `gemini_client.py`의 `_build_prompt()`에서 추가로 조립됨:
- `[상세 데이터]`: 환경, 호흡, 체온, 주간/낮잠 요약
- `[일별 수면]`: 요일별 수면시간·뒤척임·각성·취침 시간 + **환경 이상치 ⚠ (2026-05-28 추가)**
- `[지난 주 대비]`: 있으면 포함
- `[2주 전]`: 있으면 포함

## 프롬프트 작성 원칙

### 할 것
- 구체적 수치 기준 명시 ("40분↑" "6개월+")
- AI가 직접 비교할 수 있는 데이터 제공 (일별 환경 ⚠ 표기)
- 판단 예시 포함 ("뒤척임 40분↑ + 환경 양호 → Sleep Prop 의심")

### 하지 말 것
- 모호한 지시 ("적절히 판단하라" → AI가 generic 답변 생성함)
- 과도한 제약 (창의성까지 막으면 답변이 단조로워짐)
- 토큰 낭비 (같은 내용 반복 금지)

## 향후 개선 방향

| 항목 | 우선순위 | 설명 |
|------|---------|------|
| 발달 케어 DB 연동 | ★★★ | age_kick을 Gemini 생성 → 검증된 DB 조회 방식으로 전환 |
| 분리수면 진행 단계 추적 | ★★ | 주차별 분리수면 진행도를 컨텍스트에 포함 |
| 이전 ai_comment 참조 | ★★ | "지난주 조언대로 해보셨나요?" 연속성 있는 코멘트 |
| 프롬프트 A/B 테스트 | ★ | 출력 품질 비교 측정 체계 |
