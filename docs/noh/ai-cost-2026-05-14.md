## 2. 호출당 토큰 수 추정

모듈 로드 시 5개 파일을 이어붙여 단일 `system_instruction`으로 전달한다.

| 파일 | 크기 (bytes) | 추정 토큰 |
|------|------------|---------|
| `system.md` | 841 | ~210 |
| `knowledge.md` | 5,734 | ~1,433 |
| `age_policy.md` | 634 | ~159 |
| `reasoning.md` | 400 | ~100 |
| `output_format.md` | 3,040 | ~760 |
| 구분자 `---` × 4 | — | ~20 |

> 토큰 추정 기준: 한국어·영어 혼합 텍스트 평균 4 bytes/token.  
> `knowledge.md`가 전체의 54%를 차지한다.

## 6. 비용 절감 방안

### 방안 1: Thinking 최소화 ✅ 적용 완료

`gemini_client.py`에 `thinking_config=types.ThinkingConfig(thinking_level="minimal")` 적용됨.  
Gemini 3 시리즈는 thinking 완전 비활성화를 지원하지 않아 `minimal`(사실상 비활성화에 가장 가까운 설정)을 사용한다.

---

### 방안 2: Context Caching — 시스템 프롬프트 캐싱 (규모 커지면 효과적)

시스템 프롬프트 (~2,680 tokens)를 Google 측에 캐싱하면 캐시 읽기 단가(₩41/1M)로 변경.

| 항목 | 미캐싱 | 캐싱 후 |
|------|-------|-------|
| 시스템 프롬프트 입력 비용/호출 | ₩0.92 | ₩0.09 |
| 절감액/호출 | — | ₩0.83 |
| 절감율 | — | **~90%** |
| 캐시 저장 비용 | — | ₩0.0037/시간 (아주 저렴) |

**실질 효과**: 입력 비용의 약 80% 절감 (₩1.15 → ₩0.30/호출).  
**주의**: `google-genai` SDK에서 `cached_content` 설정 필요, TTL 관리 추가 구현 필요.

---

### 방안 3: Batch API (실시간 불필요한 경우)

**효과**: 전체 비용 50% 절감 → 호출당 ₩1.6 수준.  
**제약**: 비동기 처리로 응답 지연 발생 — 현재 `POST /generate` 즉시 응답 구조와 맞지 않음.  
적용 가능 케이스: 야간 배치 생성 후 아침에 제공하는 방식으로 전환 시.
