## 1. 수정된 파일

### 1.1 `backend/app/domain/report/entity.py`

**변경 전:** `Users`, `Daily_Sleep_Logs`, `Environment_Logs`, `Event_Logs`, `Generated_Reports` 5개 테이블 정의 (user_id FK 기반)

**변경 후:** 2개 테이블로 축소, ser_no 식별 방식 적용

```python
class WeeklyData(Base):
    __tablename__ = "Weekly_Data"
    id, ser_no, week_start
    sleep_json  # JSON: [{date, sleep_min, restless_min}, ...]
    env_json    # JSON: {temp_avg, temp_max, temp_min, db_max, db_avg}
    event_json  # JSON: {cry_count, leave_count}
    created_at
    # UNIQUE(ser_no, week_start)

class GeneratedReport(Base):
    __tablename__ = "Generated_Reports"
    id, ser_no, week_start
    report_json  # JSON: 최종 리포트 전체
    ai_comment   # Text
    created_at
    # UNIQUE(ser_no, week_start)
```

**핵심 변경 이유:**
- `Users` 테이블 제거 → 개인정보(이름·생년월일·이메일) 미보관
- 일별 행 단위 저장 → 주간 JSON 통합 저장 (AI 컨텍스트 구성 단순화)
- `is_deleted` 소프트 삭제 제거 → 3주 rolling 물리 삭제로 대체

### 1.2 `backend/app/domain/report/schemas.py`

**변경 전:** `ReportResponse`, `ReportRequest` (user_id 기반 단순 스키마)

**변경 후:** 요청/응답 전체 스키마 재설계

```
GenerateReportRequest
├── ser_no, baby_age_months, week_start
├── sleep: List[SleepDay]       # sleep_min: int (분 단위, "9h30m" 문자열 아님)

GenerateReportResponse
├── ser_no, week_start, week_label, generated_at
├── summary: ReportSummary
├── daily: List[DailySummary]
```

**핵심 변경 이유:**
- `sleep_min: int` 도입 → `"9h30m"` 문자열 파싱 로직(`_parse_hours`, `_parse_minutes`) 전면 제거
- `TrendData` 신규 추가 → 3주치 추이 데이터 제공
- `baby_age_months` 맘아이 서버가 계산해서 전달 → 이 서버에서 생년월일 불필요

```
  └── Step 4: report_repo.save_report() → GenerateReportResponse 리턴
```

### 2.3 `backend/app/infrastructure/database/repository/etf_repo.py`

커서 기반 페이지네이션 핵심 로직:

```python
def get_rebalancing_history_page(db, ser_no, cursor, limit):
    query = db.query(RebalancingHistory).filter(ser_no == ser_no)
    if cursor:
        query = query.filter(rebalancing_id < cursor)   # 커서보다 오래된 것만
    rows = query.order_by(desc(rebalancing_id)).limit(limit + 1).all()
    # limit+1 조회 → has_next 판단, COUNT 쿼리 없음
    has_next    = len(rows) > limit
    next_cursor = rows[limit-1].rebalancing_id if has_next else None
    return rows[:limit], next_cursor
```

### 2.5 `backend/app/application/etf/rebalance_service.py`

리밸런싱 알고리즘:
1. 시장가 fetch
2. 현재 보유 비중 계산 (수량 × 시장가 / 총 평가액)
3. 목표 비중과 drift 계산
4. `|drift| < 5%` → HOLD / 양수 → BUY / 음수 → SELL
5. `dry_run=False`일 때만 이력 DB 저장
