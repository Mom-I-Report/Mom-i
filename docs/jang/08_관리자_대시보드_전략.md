# 📊 Mom-i 관리자 대시보드(Admin) 구축 및 연기 전략

> **의사결정 요약:** 
> 리포트 생성 지표 및 비용 관리를 위한 관리자 대시보드의 필요성은 100% 인정하나, 초기 MVP(1차 오픈) 단계에서는 **직접 개발을 보류(Phase 2로 연기)** 합니다.

---

## 1. 지금 당장 개발을 미루는 이유 (Why Postpone?)

### ① 코어 밸류(고객 경험)에 100% 리소스 집중
현재 우리 개발팀의 가장 중요한 미션은 "엄마들이 보고 만족하는 고품질 AI 수면 리포트"를 문제없이 서비스하는 것입니다. 관리자 화면을 위한 프론트엔드 UI 설계와 백엔드 API 추가 개발에 리소스를 분산시키면, 정작 가장 중요한 메인 서비스의 완성도가 떨어지거나 일정이 지연될 위험이 큽니다.

### ② 이미 훌륭한 대체제가 존재함 (개발 불필요)
당장 지표 확인이 필요하더라도 직접 바닥부터 개발할 필요는 없습니다. 백엔드에서 리포트 생성 시 DB(`Generated_Reports` 등)에 데이터만 충실히 쌓아둔다면, 아래 방법으로 즉각적인 모니터링이 가능합니다.
- **개발자 직접 확인:** DBeaver 같은 데이터베이스 툴이나 백엔드 ORM(Prisma Studio 등)에서 쿼리 조회.
- **무료 BI 툴 연동:** Metabase(메타베이스)나 Retool(리툴) 같은 무료 상용 시각화 툴을 DB에 붙이면, 10분 만에 훌륭한 관리용 차트를 띄울 수 있습니다.

### ③ 유연한 기획 변경 대비
서비스 초기에는 데이터 테이블 구조나 모니터링 기준(KPI)이 자주 바뀝니다. 로직이 완전히 안정화된 이후(Phase 2)에 관리자 페이지를 만들어야 두 번 개발하는 낭비를 막을 수 있습니다.

---

## 2. 향후 구축할 관리자 대시보드 구성안 (Phase 2)

서비스가 안정화된 이후 정식으로 구축할 관리자 대시보드의 핵심 구성안(백로그)입니다.

### 📈 메인 KPI 대시보드
- **활성 기기 현황:** 이번 주 리포트를 실제로 수신/열람한 활성 카메라 및 유저 수
- **리포트 생성 건수:** 전체 누적 생성 건수 및 주차별 생성 건수 트렌드

### 💸 LLM(Gemini) 비용 추적기 (Cost Tracker)
- **API 호출 통계:** 리포트 생성 및 분석에 사용된 Gemini 시스템 총 호출 횟수
- **비용 예측:** 호출 횟수 대비 예상 청구 비용 계산 (서버 유지비 외의 가장 큰 변동비 관리)

### ⚙️ 시스템 모니터링 & 로그
- **성공/실패 비율:** 백엔드 자동 분석 스케줄링이 실패(에러) 없이 정상 발송되었는지 확인 (에러율 추적)
- **에러 로그 조회:** 분석 로직 실패 시 어떤 유저(ser_no)의 데이터에서 터졌는지 바로 확인할 수 있는 로깅 탭
