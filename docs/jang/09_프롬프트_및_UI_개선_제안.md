# 🚀 Mom-i 리포트 프롬프트 및 UI 개선 제안서

본 문서는 백엔드 팀의 AI 프롬프트 초안을 분석한 후, 리포트의 사용자 경험(UX) 극대화 및 A4 레이아웃 최적화를 위해 제안하는 **프론트엔드 UI 추가 건**과 **백엔드 프롬프트 삭제 건**의 사유와 방향성을 정리한 문서입니다.

---

## 1. 프론트엔드 UI 추가: "수면 종합 요약(총평)" 영역

### 💡 변경 내용
프론트엔드의 상단 일주일 데이터 표(테이블) 바로 아래에 **"💬 AI 종합 의견 (Summary)"** 텍스트 영역을 새롭게 추가합니다. (프론트엔드 담당자가 직접 진행)

### 🤔 추가하는 이유 (Why)
1. **프롬프트 응답 매핑 공간 필요:** 백엔드 프롬프트 초안의 `1. 수면 요약` 및 `2. 현재 상태 해석`에서 반환되는 2~3줄 분량의 줄글(Narrative)을 자연스럽게 렌더링할 전용 공간이 필수적입니다.
2. **문맥의 자연스러움:** 기존 프론트엔드에 있는 '팁 박스(뱃지형)'에 이 긴 요약글을 욱여넣으면 시각적으로 부자연스럽습니다. 수치(표) 데이터를 본 직후 AI의 전반적인 코멘트를 한 번 읽고, 그 다음 구체적인 솔루션(쉬닥법 등)으로 넘어가는 것이 부모 입장에서 훨씬 매끄럽게 읽힙니다.

### 🛠 어떤 식으로 고치는가 (How)
- **프론트엔드 수정:** `main.ts` 및 `style.css`를 수정하여, 데이터를 요약해 주는 가독성 높은 박스 컴포넌트를 디자인하여 상단에 배치합니다.

---

## 2. 기획/백엔드 프롬프트 삭제 요구: "3. 가능한 수면법 옵션"

### 💡 변경 내용
백엔드 프롬프트 `6_OUTPUT FORMAT.md.txt`에 명시된 **"3. 가능한 수면법 옵션" (대안들을 설명해주는 부분)** 파트를 프롬프트에서 완전히 삭제해달라고 요청합니다.

### 🤔 삭제를 요구하는 이유 (Why)
1. **프리미엄 리포트 컨셉 유지 (가장 중요):** 우리 서비스의 지향점은 부모에게 "선택 장애가 오는 백과사전식 정보 나열"을 하는 것이 아니라, "우리 아이 데이터를 분석해 **가장 확률이 높은 단 1가지 솔루션(Kick)을 골라 실행하라고 등 떠밀어주는 것**"입니다. 여러 옵션을 보여주는 것은 서비스의 핵심 가치(Kick)를 흐리게 합니다.
2. **레이아웃 공간 부족:** A4 프린트 최적화 및 모바일 1페이지 분량을 타겟팅한 디자인입니다. 채택되지 않은 다른 수면법들까지 구구절절 설명하게 되면 공간이 턱없이 부족해지고, 정말 읽어야 할 '오늘 밤 실행 가이드'의 가독성이 심각하게 훼손됩니다.
3. **비용(API 토큰) 절감:** 불필요한 대안들까지 LLM이 설명하게 만들면 출력 토큰(Output Token) 수가 기하급수적으로 늘어나 제미나이(Gemini) 호출 비용이 크게 증가합니다.

### 🛠 어떤 식으로 고치는가 (How)
- **팀원에게 전달할 사항 (커뮤니케이션):** "프론트엔드 화면이 깔끔하게 '1가지 맞춤 추천'에만 포커싱하도록 A4 최적화가 끝났습니다. 여러 옵션을 나열하면 지저분해지고 API 비용만 늘어나니, `6_OUTPUT FORMAT` 프롬프트에서 3번(가능한 옵션) 파트는 아예 날리고 바로 4번(추천 수면법 1개)으로 넘어가게 수정해 주세요."
