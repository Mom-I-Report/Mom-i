## 1~2주차 — Foundation (설계 및 환경 확정)

### 목표
> 개발을 위한 모든 기반을 확정한다. 이후 단계에서 스펙 변경 없이 진행 가능한 상태 만들기.

### 세부 작업

#### 🔵 데이터 규격 정의
- [ ] 카메라 → 서버 전송 JSON 스키마 확정
  ```json
  { "cameraId", "sessionDate", "bedtime", "wakeTime",
    "totalMinutes", "actualSleepMinutes", "tossingMinutes",
    "avgTemperature", "avgNoiseDb", "rawDataPath" }
  ```
- [ ] 수면 데이터 전송 주기 결정 (1일 1회 또는 실시간)
- [ ] 엠테이크 측 기존 데이터 스펙 확인 및 조율

#### 🔵 인프라 셋업
- [ ] AWS 계정 생성 및 서울 리전 설정
- [ ] EC2 인스턴스 생성 (t4g.micro → 개발용)
- [ ] RDS PostgreSQL 생성 및 Prisma 스키마 마이그레이션
- [ ] S3 버킷 생성 (리포트 저장용)
- [ ] 도메인 등록 + SSL 설정 (ACM)
- [ ] 로컬 Docker 환경 세팅 (`docker-compose.yml`)

#### 🔵 LLM 선정
- [ ] Gemini 1.5 Flash API 연동 테스트
- [ ] GPT-4o Mini 비교 테스트
- [ ] 개월수별 기본 프롬프트 초안 작성
- [ ] 비용/품질 결과 비교표 작성 → 최종 모델 결정

#### 🔵 프론트엔드 기반
- [ ] 더미 데이터 기반 UI 프로토타입 완성 (현재 작업 중)
- [ ] 디자인 시스템 확정 (색상, 폰트, 컴포넌트)

### 산출물 (Deliverable)
- `docs/04_데이터베이스_스키마.md` — DB 스키마 확정본
- `docs/03_백엔드.md` — API 규격서
- AWS 인프라 세팅 완료 스크린샷
- LLM 비교 결과 보고서

## 3~4주차 — Logic Dev (데이터 분석 엔진)

### 목표
> 실제 기기 없이도 개발 가능한 시뮬레이터를 만들고, 핵심 분석 로직을 완성한다.

### 세부 작업

#### 🟢 데이터 시뮬레이터 구축
- [ ] 다양한 수면 케이스 생성기 개발
  - 정상 케이스 (점수 80~95)
  - 불규칙 케이스 (뒤척임 많음, 점수 50~70)
  - 고온 환경 케이스 (온도 24°C↑)
  - 데이터 누락 케이스 (특정 날 데이터 없음)
- [ ] 시뮬레이터 스크립트 → `/scripts/simulator.ts`

#### 🟢 수면 분석 알고리즘
- [ ] 일별 수면 점수 계산 함수
  - 실수면 비율 (40점), 총 수면 (30점), 온도 (20점), 소음 (10점)
- [ ] 주간 집계 로직 (평균, 추이, Best/Worst)
- [ ] 이상치 감지 (온도 초과, 뒤척임 급증 등)
- [ ] 단위 테스트 작성 (Jest)

#### 🟢 LLM 리포팅 최적화
- [ ] 개월수별 프롬프트 고도화 (0~3M, 4~6M, 7~9M, 10~12M)
- [ ] 과거 데이터 컨텍스트 반영 로직
- [ ] JSON 응답 파싱 및 검증
- [ ] fallback 로직 (LLM 실패 시 템플릿 기반 텍스트)

### 산출물 (Deliverable)
- `scripts/simulator.ts` — 데이터 시뮬레이터
- `src/services/sleepAnalysis.ts` — 분석 엔진
- `src/services/llmService.ts` — LLM 서비스
- 분석 엔진 프로토타입 (테스트 통과 증명)

## 5~6주차 — System Build (리포트 자동생성 + UI/UX)

### 목표
> 데이터 → 분석 → AI 텍스트 → 리포트 자동 생성 파이프라인 완성. 프론트 통합.

### 세부 작업

#### 🟡 리포트 자동생성 파이프라인
- [ ] AWS Lambda 스케줄러 설정 (매주 월요일 오전 7시)
- [ ] 리포트 생성 오케스트레이터 (`reportGenerator.ts`)
  ```
  주간 데이터 취합 → 분석 엔진 → LLM → 리포트 저장 → 알림 발송
  ```
- [ ] DynamoDB 캐시 저장 로직
- [ ] S3 리포트 파일 저장 (JSON + 추후 PNG 확장)

#### 🟡 히스토리 관리
- [ ] 4~8주 분량 리포트 보관 로직
- [ ] 히스토리 조회 API (`GET /reports`)
- [ ] 점수 추이 계산 (이전 주 대비)

#### 🟡 프론트엔드 통합
- [ ] API 클라이언트 모듈 (`src/api/reportsApi.ts`)
- [ ] 더미 데이터 → 실 API 전환 준비 (환경변수 스위치)
- [ ] 리포트 공유 기능 (이미지 저장 / URL 복사)

#### 🟡 중간 시연 준비
- [ ] 실제 리포트 샘플 5개 생성
- [ ] 엠테이크 측 데모 환경 구성 (dev 서버)

### 산출물 (Deliverable)
- 리포트 생성 자동화 파이프라인 동작
- 주간 리포트 샘플 5개
- 프론트엔드 + 백엔드 통합 동작 데모

## 7주차 — 엠테이크 피드백 반영

### 목표
> 중간 시연 결과를 바탕으로 수정사항을 반영한다.

### 예상 수정 항목
- [ ] 리포트 디자인 톤앤매너 수정 (색상, 폰트, 레이아웃)
- [ ] AI 분석 텍스트 톤 조정 (너무 딱딱하거나 너무 가벼운 경우)
- [ ] 데이터 수집 스펙 변경사항 반영
- [ ] 추가 기능 요청 사항 검토 및 일정 조율

## 8~9주차 — Refine (정교화)

### 목표
> 리포트 품질을 실제 서비스 수준으로 높인다.

### 세부 작업

#### 🔴 프롬프트 정교화
- [ ] 프롬프트 A/B 테스트 (여러 버전 비교)
- [ ] 주변 지인 베타 테스트 (5~10명)
- [ ] 피드백 기반 프롬프트 개선
- [ ] 응답 일관성 검증 (같은 데이터 입력 시 유사한 품질 출력)

#### 🔴 분석 정확도 향상
- [ ] 개월수별 권장값 정밀화 (소아과 가이드라인 기반)
- [ ] 뒤척임 이상 임계값 조정
- [ ] 수면 점수 보정 (실사용자 피드백 반영)

#### 🔴 성능 최적화
- [ ] 리포트 생성 시간 측정 및 최적화 목표: 5초 이내
- [ ] 캐싱 전략 검증
- [ ] N+1 쿼리 문제 점검

---

## 10~12주차 — Delivery (앱 연동 + 최종 인도)

### 목표
> 엠테이크 측 앱과 완전히 연동하고, 운영 가능한 상태로 인도한다.

### 세부 작업

#### ⚫ 앱 API 연동 지원
- [ ] 엠테이크 앱 팀과 API 연동 협업
- [ ] CORS 설정, 인증 토큰 방식 결정
- [ ] 앱 리뷰용 API 문서 작성 (Swagger 또는 Postman Collection)
- [ ] 테스트 계정 및 테스트 데이터 제공

#### ⚫ 부하 테스트
- [ ] 동시 접속 시뮬레이션 (100~500명)
- [ ] 리포트 생성 속도 측정
- [ ] LLM Token 사용량 최종 산출 → 월 비용 추정

#### ⚫ 운영 준비
- [ ] CloudWatch 대시보드 설정
- [ ] 에러 알림 설정 (Slack Webhook)
- [ ] 자동 백업 설정 (RDS 스냅샷)
- [ ] EC2 → t4g.small 업그레이드 (소규모 운영)

#### ⚫ 인수인계
- [ ] 최종 소스코드 패키징
- [ ] 서버 운영 매뉴얼 작성
- [ ] 운영 비용 가이드 작성 (시나리오별 예상 비용)
- [ ] 프로젝트 완료 보고서 제출

### 산출물 (Deliverable)
- 최종 소스코드 (GitHub 또는 압축 파일)
- API 문서 (Swagger)
- 서버 운영 매뉴얼
- 운영 비용 가이드
- 프로젝트 완료 보고서
